## Лекция: Google reCAPTCHA v3 — Невидимый страж вашего сайта

Представьте, что вы владелец интернет-магазина. Каждый день тысячи людей заходят к вам: одни хотят купить товар, другие — оставить спам в комментариях, третьи — автоматически скупить весь товар ботами. Как отличить человека от бота, не заставляя покупателей проходить утомительные тесты?

**Ответ:** Google reCAPTCHA v3 — это невидимый охранник, который оценивает каждого посетителя по шкале от 0 до 1 и тихо говорит вам: "Этому пользователю я доверяю на 90%, а этому — только на 10%".

### 1. Что такое reCAPTCHA v3 простыми словами

**reCAPTCHA v3** — это эволюция капчи от Google. Если старые версии (v2) заставляли пользователя что-то делать (нажать флажок "Я не робот" или выбрать картинки с гидрантами), то v3 работает **полностью в фоне** .

**Аналогия:** 
- **reCAPTCHA v2** = охранник, который каждому входящему задаёт вопрос: "Назовите столицу Франции"
- **reCAPTCHA v3** = охранник-невидимка, который наблюдает за поведением посетителя: как он ходит, как смотрит по сторонам, как достаёт кошелёк. И только если поведение странное — подходит проверить документы.

### 2. Как это работает: от первого клика до оценки

```
┌─────────────────────────────────────────────────────────────────────┐
│                    ПОТОК РАБОТЫ reCAPTCHA v3                        │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  1. Пользователь заходит на сайт                                    │
│           ↓                                                         │
│  2. Браузер загружает JavaScript-библиотеку reCAPTCHA              │
│           ↓                                                         │
│  3. reCAPTCHA начинает НЕВИДИМО собирать данные о поведении:       │
│     • Как двигается мышь                                           │
│     • С какой скоростью скроллит страницу                          │
│     • Как печатает на клавиатуре                                   │
│     • Какой IP-адрес и браузер                                      │
│           ↓                                                         │
│  4. Пользователь нажимает кнопку "Войти"                           │
│           ↓                                                         │
│  5. Ваш код вызывает grecaptcha.execute() с названием действия     │
│           ↓                                                         │
│  6. Google возвращает ОДНОРАЗОВЫЙ ТОКЕН (живёт 2 минуты)           │
│           ↓                                                         │
│  7. Ваш сервер отправляет токен в Google для верификации           │
│           ↓                                                         │
│  8. Google возвращает ОЦЕНКУ (score) от 0.0 до 1.0                 │
│     • 1.0 = почти точно человек                                     │
│     • 0.0 = почти точно бот                                         │
│           ↓                                                         │
│  9. ВАШ сервер решает, что делать:                                  │
│     • score > 0.7 → пропустить                                      │
│     • score 0.3-0.7 → попросить подтверждение по email             │
│     • score < 0.3 → заблокировать                                   │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 3. Ключевая концепция: "Action" (действие)

Одна из главных инноваций v3 — **параметр action** . Когда вы вызываете `grecaptcha.execute()`, вы передаёте строку с названием действия:

```javascript
// Пример на фронтенде
grecaptcha.execute('SITE_KEY', {action: 'login'})
grecaptcha.execute('SITE_KEY', {action: 'checkout'})
grecaptcha.execute('SITE_KEY', {action: 'comment'})
```

**Зачем это нужно:**
- Разные действия могут иметь разный уровень риска. Логин может быть более подозрительным, чем просмотр каталога.
- В консоли администрирования Google вы увидите статистику по каждому action отдельно 
- Вы можете защититься от **token replay attacks** — когда бот получает токен на безопасной странице, а использует на критичной

### 4. Что означает оценка (score)

Google возвращает число от 0.0 до 1.0. Чем выше — тем больше доверия :

| Оценка | Интерпретация | Рекомендуемое действие |
|--------|---------------|----------------------|
| **0.9 - 1.0** | Почти точно человек | Пропустить без вопросов |
| **0.7 - 0.9** | Вероятно, человек | Пропустить, но логировать |
| **0.5 - 0.7** | Не уверен | Запросить email-подтверждение или 2FA |
| **0.3 - 0.5** | Подозрительно | Отправить на модерацию, задержать запрос |
| **0.0 - 0.3** | Почти точно бот | Заблокировать или показать капчу v2 |

**Важно:** Google рекомендует начинать с порога 0.5 и настраивать под свой сайт . Интернет-магазин может установить порог 0.7 для оформления заказа, но 0.3 для подписки на новости.

### 5. Чего reCAPTCHA v3 НЕ делает (важно понять!)

Многие разработчики ошибочно полагают, что reCAPTCHA v3 сама блокирует ботов. Это **НЕ ТАК** :

| Миф | Реальность |
|-----|------------|
| "reCAPTCHA блокирует ботов" | ❌ НЕТ. Она возвращает ОЦЕНКУ. Блокируете ВЫ своим кодом |
| "Боты всегда получают 0.0" | ❌ НЕТ. Сложные боты могут имитировать поведение человека и получить высокий балл |
| "Она сама подбирает порог" | ❌ НЕТ. Порог настраиваете ВЫ |
| "Она работает на всех страницах" | ⚠️ Только там, где вы установили виджет |

### 6. Жизненный цикл токена (критично для backend)

```
ВРЕМЕННАЯ ШКАЛА ТОКЕНА:
─────────────────────────────────────────────────────────────────

0 сек:   Пользователь нажал кнопку
         → grecaptcha.execute() вызван
         
0.5 сек: Google вернул токен: "03AGdBq25..."
         → Токен действителен 120 секунд!
         
1 сек:   Фронтенд отправил токен на ваш сервер
         
2 сек:   Ваш сервер вызывает Google API:
         POST https://www.google.com/recaptcha/api/siteverify
         ?secret=YOUR_SECRET_KEY&response=03AGdBq25...
         
3 сек:   Google отвечает: { "success": true, "score": 0.9, "action": "login" }
         
... 2 минуты прошло ...
         
120 сек: Токен истёк
         → При повторной проверке вернётся ошибка "timeout-or-duplicate"
         
         Токены нельзя использовать дважды — это защита от повторного воспроизведения!
```

### 7. Сравнение версий reCAPTCHA

| Характеристика | reCAPTCHA v2 | reCAPTCHA v3 |
|----------------|--------------|--------------|
| **Что видит пользователь** | Флажок или картинки | Ничего (невидимо) |
| **Результат** | Успех/неудача (бинарно) | Оценка 0.0–1.0 |
| **Удобство для людей** | Низкое (прерывает действие) | Высокое (без прерываний) |
| **Контроль разработчика** | Низкий (Google решает) | Высокий (вы решаете) |
| **Сложность интеграции** | Низкая (2 строки HTML) | Средняя (frontend + backend + логика) |
| **Аналитика** | Базовая | Детальная по action |
| **Доступность** | Проблемы для людей с ограничениями | Полностью доступна |

### 8. Как внедрить reCAPTCHA v3 (шпаргалка для разработчика)

#### Frontend (на странице):

```html
<!-- 1. Добавить скрипт -->
<script src="https://www.google.com/recaptcha/api.js?render=YOUR_SITE_KEY"></script>

<script>
// 2. При отправке формы
document.getElementById('login-form').addEventListener('submit', function(e) {
    e.preventDefault();
    
    grecaptcha.ready(function() {
        // 3. Вызвать execute с action
        grecaptcha.execute('YOUR_SITE_KEY', {action: 'login'}).then(function(token) {
            // 4. Добавить токен в форму и отправить
            document.getElementById('recaptcha-token').value = token;
            document.getElementById('login-form').submit();
        });
    });
});
</script>
```

#### Backend (проверка):

```php
// 5. Получить токен из POST-запроса
$token = $_POST['recaptcha_token'] ?? '';

// 6. Отправить запрос к Google
$response = file_get_contents(
    'https://www.google.com/recaptcha/api/siteverify?' . http_build_query([
        'secret' => 'YOUR_SECRET_KEY',
        'response' => $token,
        'remoteip' => $_SERVER['REMOTE_ADDR']
    ])
);

$result = json_decode($response, true);

// 7. Проверить и принять решение
if ($result['success'] && $result['score'] >= 0.5) {
    // Пропускаем пользователя
} else {
    // Блокируем или запрашиваем дополнительную проверку
}
```

## 3 Проверочных вопроса

### Вопрос 1 (легкий)
**В чем главное отличие reCAPTCHA v3 от reCAPTCHA v2 с точки зрения пользователя?**

<details>
<summary>Ответ</summary>

**Главное отличие: v3 ничего не показывает пользователю.**

- **reCAPTCHA v2** требует от пользователя действия: нажать флажок "Я не робот" или выбрать картинки с гидрантами/автобусами. Это прерывает пользовательский опыт .

- **reCAPTCHA v3** работает полностью в фоне. Пользователь даже не знает, что его проверяют. Google анализирует поведение (движения мыши, скролл, историю браузера) и возвращает сайту оценку. Сам пользователь не видит никаких тестов .

**Аналогия:** v2 — это охранник, который каждому задаёт вопрос. v3 — это система распознавания лиц на входе: вы просто проходите, а система оценивает, кто вы.
</details>

### Вопрос 2 (средний)
**Что такое "action" в reCAPTCHA v3 и зачем он нужен?**

<details>
<summary>Ответ</summary>

**Action** — это метка, которую разработчик передаёт при вызове `grecaptcha.execute()` .

**Пример:**
```javascript
grecaptcha.execute(SITE_KEY, {action: 'login'})    // для страницы входа
grecaptcha.execute(SITE_KEY, {action: 'checkout'}) // для оформления заказа
grecaptcha.execute(SITE_KEY, {action: 'comment'})  // для отправки комментария
```

**Зачем это нужно:**

1. **Разные пороги для разных действий** — логин можно проверять строже, чем просмотр каталога
2. **Аналитика в консоли Google** — вы видите оценки отдельно для login, checkout, comment и т.д.
3. **Защита от подмены (token replay)** — ваш сервер проверяет, что токен получен именно для действия `login`, а не для `comment`

**Без action бот мог бы получить токен на странице с низким риском (например, поиск) и использовать его на странице входа в систему .**
</details>

### Вопрос 3 (сложный)
**Почему reCAPTCHA v3 не блокирует ботов автоматически? В чём философия этого подхода?**

<details>
<summary>Ответ</summary>

**reCAPTCHA v3 — это ИНФОРМАТОР, а не БЛОКИРОВЩИК** .

**Философия Google:** "Мы даём вам данные (оценку), а вы сами решаете, что с ними делать, потому что вы лучше знаете свой бизнес".

**Почему это правильно:**

| Пользователь | Что лучше для сайта |
|--------------|---------------------|
| Новый посетитель без истории | Для интернет-магазина оценка 0.4 может быть приемлема, для банка — нет |
| Пользователь из страны с плохой репутацией | Возможно, стоит усилить проверку, а не блокировать |
| Пользователь в Tor | Можно потребовать email-подтверждение вместо полной блокировки |

**Примеры разных решений для оценки 0.4:**

- **Форма подписки на новости:** можно пропустить
- **Страница входа в интернет-банк:** запросить 2FA
- **Оформление заказа на $1000:** отправить на ручную модерацию

**Итог:** Google не знает ваш бизнес. reCAPTCHA v3 даёт вам оценку, а вы принимаете решение. Это даёт гибкость, но требует от вас продуманной логики .
</details>
