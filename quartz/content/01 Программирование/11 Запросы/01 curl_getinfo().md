
## Лекция: Диагностика HTTP-запросов в PHP с помощью `curl_getinfo()`

### 1. Что такое `curl_getinfo()`?

Представьте, что ваш PHP-скрипт — это курьер, который отправляется на удаленный сервер (в данном случае `service.nalog.ru`) за посылкой (веб-страницей). `curl_getinfo()` — это детальный отчет курьера о всей поездке:

- Сколько времени ехал?
- Какой маршрут выбрал?
- Не было ли аварий (ошибок)?
- Какой вес посылки?
- По какому протоколу общался?

**Формула:**
```php
$ch = curl_init();          // наняли курьера
curl_setopt($ch, CURLOPT_URL, "https://service.nalog.ru/bi.do");
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
curl_exec($ch);             // отправили
$info = curl_getinfo($ch);  // получили отчет
curl_close($ch);
```

### 2. Разбор ключей вашего массива (группировка по смыслу)

#### Группа А: Итоги поездки
| Ключ | Значение | Перевод на русский |
|------|----------|-------------------|
| `http_code` | 200 | Всё отлично (OK) |
| `total_time` | 1.136 сек | Вся операция заняла чуть больше секунды |
| `size_download` | 26213 байт | Скачано ~25.6 КБ данных |
| `speed_download` | 23074 байт/с | Средняя скорость ~22.5 КБ/с |

> **Вывод:** Сервер работает штатно, страница загрузилась нормально.

#### Группа Б: Технические детали соединения
| Ключ | Значение | Что значит |
|------|----------|-------------|
| `primary_ip` | 193.3.23.126 | IP-адрес сервера ФНС |
| `primary_port` | 51531 | Нестандартный порт (обычно 443 для HTTPS) |
| `scheme` | HTTPS | Использовано шифрование |
| `ssl_verify_result` | 0 | SSL-сертификат валидный |
| `protocol` | 2 | HTTP/2 (современный протокол) |

> **Важно:** Порт 51531 — особенность сервера nalog.ru. Обычные сайты используют 443.

#### Группа В: Тайминг — самая полезная часть для отладки
Время указано в секундах (чем меньше, тем лучше):

| Этап | Ключ | Значение | Аналогия |
|------|------|----------|-----------|
| DNS-запрос | `namelookup_time` | 0.000015 с | Найти адрес дома по названию улицы |
| Установка TCP | `connect_time` | 0.016689 с | Позвонить в дверь |
| SSL-рукопожатие | `pretransfer_time` | 1.091163 с | Предъявить пропуск (самый долгий этап) |
| Ожидание первого байта | `starttransfer_time` | 1.119514 с | Ждать, пока откроют дверь |
| Общее время | `total_time` | 1.136447 с | Вся поездка |

**Практический вывод:** Основное время (1.09 с) ушло на согласование SSL-соединения. Если ваш сайт тормозит — смотрите на `pretransfer_time`.

### 3. Как это используют на практике?

#### Пример 1: Проверка доступности API
```php
<?php
$ch = curl_init("https://service.nalog.ru/bi.do");
curl_setopt($ch, CURLOPT_NOBODY, true); // только заголовки
curl_exec($ch);
$code = curl_getinfo($ch, CURLINFO_HTTP_CODE);

if ($code == 200) {
    echo "Сервер жив";
} elseif ($code >= 500) {
    echo "Ошибка на сервере ФНС";
}
```

#### Пример 2: Мониторинг скорости
```php
$info = curl_getinfo($ch);
if ($info['total_time'] > 2) {
    mail('admin@site.ru', 'Медленный ответ от ФНС', "Время: " . $info['total_time']);
}
```

#### Пример 3: Отладка редиректов
```php
curl_setopt($ch, CURLOPT_FOLLOWLOCATION, true);
$info = curl_getinfo($ch);
echo "Было редиректов: " . $info['redirect_count'];
```

### 4. Самые полезные константы для `curl_getinfo()`

Вместо `$info['http_code']` можно использовать константы:

| Константа | Что возвращает |
|-----------|----------------|
| `CURLINFO_HTTP_CODE` | Код ответа (200, 404, 500) |
| `CURLINFO_TOTAL_TIME` | Общее время |
| `CURLINFO_SPEED_DOWNLOAD` | Скорость скачивания |
| `CURLINFO_REDIRECT_COUNT` | Количество редиректов |
| `CURLINFO_EFFECTIVE_URL` | Конечный URL после редиректов |

**Пример:**
```php
$time = curl_getinfo($ch, CURLINFO_TOTAL_TIME);
```

## 3 Проверочных вопроса (с ответами для самопроверки)

### Вопрос 1 (легкий)
**Какой ключ массива `curl_getinfo()` показывает, был ли ответ сервера успешным (страница найдена)?**

<details>
<summary>Ответ</summary>

`[http_code]` со значением 200. Коды 2xx означают успех, 4xx — ошибка клиента, 5xx — ошибка сервера.
</details>

### Вопрос 2 (средний)
**Вы заметили, что скрипт работает очень долго. На какой ключ вы посмотрите в первую очередь, чтобы понять, где именно задержка? Назовите 2 ключа.**

<details>
<summary>Ответ</summary>

1. `[pretransfer_time]` — время на установку SSL-соединения (частая проблема)
2. `[starttransfer_time]` — время до первого байта ответа (показывает, как долго сервер думает)

Если `pretransfer_time` большой — проблема с SSL/TLS. Если разница между `starttransfer_time` и `pretransfer_time` большая — медленный код на сервере.
</details>

### Вопрос 3 (сложный)
**Почему в вашем массиве `[download_content_length] = -1`, хотя данные скачались (`size_download` = 26213)?**

<details>
<summary>Ответ</summary>

`download_content_length` = -1 означает, что сервер не передал заголовок `Content-Length` при ответе. Это часто бывает при:
- Использовании chunked transfer encoding (данные передаются частями)
- Динамической генерации страницы (PHP-скрипт не знает итоговый размер заранее)

`size_download` всё равно показывает реально скачанный объем, так как curl его подсчитал сам.
</details>

## Для какой квалификации полезно знание `curl_getinfo()`?

### Основные роли:

1. **PHP-разработчик (middle → senior)**  
   - Нужно при интеграции с любыми API (платежные системы, госуслуги, соцсети)
   - Позволяет отличить: "API медленный" от "у меня проблемы с сетью"

2. **DevOps / Системный администратор**  
   - Написание скриптов мониторинга доступности сервисов
   - Диагностика сетевых проблем между серверами

3. **Разработчик парсеров (crawler / scraper)**  
   - Чтобы не банили за слишком частые запросы — нужно отслеживать скорость
   - Анализ редиректов и конечных URL

4. **Тестировщик-автоматизатор (при тестировании API)**  
   - Проверка не только тела ответа, но и метрик производительности
   - Создание нагрузочных тестов на уровне curl
