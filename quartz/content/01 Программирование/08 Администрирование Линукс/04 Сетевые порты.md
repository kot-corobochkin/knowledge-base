## Лекция: Что такое порты и почему их так много (на примере логов Node.js)

### 1. Что такое порт простыми словами

**Аналогия с многоквартирным домом:**
- **IP-адрес** (178.205.106.217) — это адрес дома
- **Порт** (3000) — это номер квартиры
- **Сервер** — это дом, где живут разные сервисы
- **Клиент** — это гость, который приходит в определенную квартиру

Без порта вы знаете, где находится дом, но не знаете, в какую квартиру стучаться.

### 2. Разбор каждого числа из вашего лога

```
[729073]: }
Apr 14 21:11:46 dpoffice node[729073]: Node.js v22.20.0
Apr 14 21:12:09 dpoffice systemd[1]: node_js.service: Succeeded.
Apr 15 11:24:13 dpoffice systemd[1]: Started node_js server app.

Worker 1745988 started on port -> 3000

http://178.205.106.217:3000
```

| Число | Что это | Объяснение |
|-------|---------|------------|
| `729073` | **PID** (Process ID) | Идентификатор процесса Node.js, который завершился |
| `22.20.0` | **Версия Node.js** | Не порт! Это версия программы (22.20.0) |
| `1745988` | **PID нового процесса** | Новый рабочий процесс (Worker) |
| `3000` | **Сетевой порт** | Порт, на котором слушает приложение |
| `178.205.106.217:3000` | **IP + порт** | Полный адрес для доступа к приложению |

### 3. Типы портов, которые вы видите

```
┌─────────────────────────────────────────────────────────────┐
│                    ПРИЛОЖЕНИЕ (Node.js)                      │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │           СЛУШАЕТ НА ПОРТУ 3000                      │   │
│  │    "Я здесь, стучитесь ко мне на 3000 квартиру!"    │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  У САМОГО ПРИЛОЖЕНИЯ ЕСТЬ:                                  │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐     │
│  │ PID: 729073  │  │ PID: 1745988 │  │ Версия:      │     │
│  │ (старый)     │  │ (новый)      │  │ 22.20.0      │     │
│  └──────────────┘  └──────────────┘  └──────────────┘     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**Важно:** PID и версия программы — **НЕ ПОРТЫ**! Это просто числа, которые случайно похожи на порты.

### 4. Диапазоны портов (почему 3000, а не 80)

| Диапазон | Название | Примеры | Кто может использовать |
|----------|----------|---------|----------------------|
| 0-1023 | **Системные (привилегированные)** | 80 (HTTP), 443 (HTTPS), 22 (SSH) | Только root |
| 1024-49151 | **Зарегистрированные** | 3000 (Node.js dev), 3306 (MySQL), 5432 (PostgreSQL) | Обычные пользователи |
| 49152-65535 | **Динамические/временные** | Временные порты для ответов клиентам | Система назначает сама |

**Почему 3000?**
- Разработчики часто используют 3000 для тестовых серверов
- Не требует прав root
- Не конфликтует с популярными сервисами
- Легко запомнить

### 6. Как порты работают на практике

**Когда вы открываете браузер и переходите на `http://178.205.106.217:3000`:**

```

   └── "Хочу поговорить с сервером на порту 3000"

2. Браузер выбирает случайный порт для себя
   └── Например, порт 54321 (временный)

3. Отправка запроса:
   ┌──────────────────────────────────────────────────────────┐
   │ ОТ:      мой IP:54321                                     │
   │ КОМУ:    178.205.106.217:3000                             │
   │ СООБЩЕНИЕ: "Дай мне страницу"                             │
   └──────────────────────────────────────────────────────────┘

4. Сервер (на порту 3000) получает запрос
   └── Node.js приложение его обрабатывает

5. Ответ возвращается:
   ┌──────────────────────────────────────────────────────────┐
   │ ОТ:      178.205.106.217:3000                             │
   │ КОМУ:    мой IP:54321                                     │

6. Браузер показывает страницу
```

### 7. Почему PID 729073 и версия 22.20.0 — не порты

**Путаница возникает, потому что числа выглядят похоже:**

| Число | Это порт? | Почему нет |
|-------|-----------|------------|
| 729073 | ❌ Нет | Максимальный порт — 65535. 729073 больше 65535 |
| 22.20.0 | ❌ Нет | Содержит точки (версия программы) |
| 3000 | ✅ Да | В диапазоне 1024-49151 |
| 1745988 | ❌ Нет | Больше 65535 (это PID процесса) |

**Правило:** Если число больше 65535 — это НЕ порт. Это PID или что-то другое.

### 8. Команды для проверки портов (практика)

```bash
# Посмотреть, какие приложения слушают какие порты
sudo netstat -tlnp

# Результат:
# tcp   0   0 0.0.0.0:3000   0.0.0.0:*   LISTEN   1745988/node
#        ↑                      ↑                    ↑
#   Порт 3000            слушает все IP         PID процесса

# Альтернативный способ
sudo ss -tlnp | grep 3000

# Посмотреть, что использует порт 3000
lsof -i :3000

# Результат:
# COMMAND   PID   USER   NAME
# node    1745988 apache  TCP *:3000 (LISTEN)
```

## 3 Проверочных вопроса

### Вопрос 1 (легкий)
**Какие три числа из лога являются портами, а какие — нет? Почему?**

<details>
<summary>Ответ</summary>

**Порты (только одно число):**
- `3000` — это порт. Он в диапазоне 1024-49151, используется для входящих соединений.

**НЕ порты:**
- `729073` — это PID (Process ID). Слишком большой (больше 65535).
- `22.20.0` — это версия Node.js. Содержит точки, это не число порта.
- `1745988` — это PID нового процесса. Тоже больше 65535.

**Правило запоминания:** Порт всегда от 1 до 65535. Всё, что больше или содержит точки — не порт.
</details>

### Вопрос 2 (средний)
**Что произошло между 21:12:09 14 апреля и 11:24:13 15 апреля? Почему приложение перезапустилось?**

<details>
<summary>Ответ</summary>

**Что произошло:** Приложение (Node.js сервер) остановилось и было перезапущено.

**Временная линия:**
- `21:12:09` — сервис успешно завершен (`Succeeded`)
- `11:24:13` (следующий день) — сервис запущен снова (`Started`)

**Причины перезапуска могут быть:**
1. **Плановая перезагрузка сервера** (ночью)
2. **Сбой в приложении** (ошибка, краш)
3. **Обновление кода** (деплой новой версии)
4. **Ручной перезапуск** администратором
5. **systemd политика** (restart=always)

**Как проверить причину:**
```bash
# Посмотреть логи systemd
journalctl -u node_js.service --since "2026-04-14 20:00:00"

# Посмотреть, не было ли перезагрузки ОС
last reboot
```
</details>

### Вопрос 3 (сложный)
**Представьте, что вы хотите запустить второе Node.js приложение на том же сервере. На каком порту вы его запустите и почему нельзя использовать порт 3000?**

<details>
<summary>Ответ</summary>

**Нельзя использовать порт 3000, потому что:**
- **Один порт может слушать только одно приложение** в один момент времени
- Это как квартира — в ней не могут жить две разные семьи одновременно
- Попытка запустить второе приложение на порту 3000 вызовет ошибку: `EADDRINUSE (Address already in use)`

**Какие порты можно использовать:**

| Порт | Почему подходит | Пример использования |
|------|----------------|---------------------|
| `3001` | Следующий после 3000 | Второе dev-приложение |
| `8080` | Стандартный для тестов | Альтернативный HTTP |
| `4000` | Тоже популярный | API-сервер |
| `5000` | Часто для микросервисов | Flask/Express приложение |

**Как выбрать правильный порт:**
```bash
# 1. Проверить, какие порты уже заняты
sudo netstat -tlnp | grep LISTEN

# 2. Выбрать свободный порт из диапазона 1024-49151
# 3. Убедиться, что порт не заблокирован фаерволом

# 4. Запустить второе приложение
node app2.js --port=3001
```

**Почему нельзя использовать системные порты (0-1023):**
- Требуют прав root (`sudo`)
- Могут конфликтовать с системными сервисами
- Потенциальная угроза безопасности
</details>

## Итоговый вывод по вашему логу

**Что вы видели в логах:**

```
[729073]: }                    ← PID старого процесса (не порт!)
Node.js v22.20.0               ← Версия программы (не порт!)
node_js.service: Succeeded     ← Сервис корректно остановился
Started node_js server app     ← Сервис запущен заново
Worker 1745988 started         ← Новый PID (не порт!)
on port -> 3000                ← А ВОТ ЭТО ПОРТ! Приложение слушает на 3000
http://178.205.106.217:3000    ← Полный адрес: IP + порт
```

**Главное понимание:**
- **Порт** — это номер квартиры, куда приходят запросы
- **PID** — это паспорт процесса (внутренний идентификатор системы)
- **Версия** — это номер версии программы
- Одно приложение = один процесс (PID) + один порт (для входящих)

**Практический вывод:** Если вы хотите проверить, работает ли приложение:
```bash
# Проверка 1: Живой ли процесс?
ps aux | grep 1745988

# Проверка 2: Слушает ли порт?
curl http://localhost:3000

# Проверка 3: Доступно ли снаружи?
curl http://178.205.106.217:3000
```

**Запоминающаяся фраза:**  
> "Порт — это дверь в приложение. IP-адрес — это улица. PID — это паспорт процесса. Не путайте номер квартиры с номером паспорта, даже если они похожи."
